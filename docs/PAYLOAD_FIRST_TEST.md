# One controlled OmniHuman test in Payload

After this branch is independently deployed, sign in to `/admin` as **Super Admin**. The dashboard's **OmniHuman 2.0 — one controlled test** panel is the only browser entrypoint. Editors, Support and customers cannot use its API or read its private inputs/results. Payload sessions, Basic Auth and exact CMS Origin remain required. No CMS schema migration is needed; small approval records live beside the existing private SQLite operator ledger.

1. Click **Refresh saved status** to reuse the existing owned plan and immutable files; no new upload is needed. Authenticated Super Admin preparation has no hourly upload quota. The 60 requests/minute safeguard, byte/media limits and all customer upload limits remain. If no plan exists, **Upload private test inputs**: one JPEG/PNG up to 5 MB, one already prepared MP3 under 15 MB measuring **4–5 seconds including encoding padding**. Confirm rights and English direction. **Prepare offline** validates the actual files, copies immutable snapshots and records hashes. No R2/provider request is made. A nominal 5-second file measuring over 5 seconds is rejected; use a shorter prepared excerpt rather than changing the limit. These are private operator inputs, not public CMS assets or customer records.
2. **Review inclusive cost**: inspect image, audio, measured duration, composed prompt and hashes. Supply the exact-input generated-duration maximum, base/tax/fee bounds in integer microUSD (1 USD = 1,000,000), total, reviewer, ISO timestamp and evidence. Use acknowledgment `INCLUSIVE_BOUND_FOR_EXACT_INPUT`. **Validate and save cost review** is offline. No amount, tax, evidence or reviewer is auto-filled. USD 0.42 before tax for the reported five-second example does not establish a tax-inclusive bound for every shorter input.
3. After saving the cost review, open **Approve output policy before start / save MP4** and approve the exact host/media policy described below. For a first discovery run, select **First-test discovery** instead: cost approval is mandatory, while host/media approval happens after polling returns the actual hostname. Discovery skips no billing or spending gate and never downloads automatically. Only after separate server authorization below, check the final **I authorize exactly ONE paid task** confirmation and click **Start ONE paid generation** once. The existing ledger claims its global one-test slot and reserves budget before R2/BytePlus. A timeout or lost HTTP response is not permission to resubmit. **Refresh saved status** reloads durable state. **Check provider status / resume same task** performs one read of the persisted task; check periodically. No background worker, auto-submit or auto-poll is added. A crash before recording a task ID leaves the existing uncertainty block; reconcile with BytePlus without resetting the ledger.
4. **Approve output policy before start / save MP4** becomes available after the inclusive cost review is saved. This pre-approval binds to that exact cost digest and then to the single persisted task, including after a restart. Changing the cost review invalidates the old policy approval. Record an explicitly reviewed exact hostname, dimensions, FPS, duration bounds, codecs, reviewer/date and evidence. `v16m-default.tiktokcdn.com` is candidate evidence only, never an automatic approval. Use acknowledgment `APPROVE_EXACT_HOST_AND_MEDIA_POLICY`. A changed hostname or mismatched file remains blocked.
5. When status is `output_observed`, save the output review, check its fetch confirmation and click **Retrieve and validate MP4 — no new generation**. This uses the existing pinned-public-IP HTTPS downloader and FFmpeg validation. Only `completed` results expose a private video player and **Download private MP4**. Provider/R2 URLs and filesystem paths never enter the browser. Fetch promptly: provider URLs expire in roughly one hour. **Refresh same-task output URL** never submits another task and cannot guarantee an extension. A failed transfer can be resumed with the same retrieval action after its existing lease expires.
6. **Cancel if still queued** retains the existing queue check and one-time cancellation safeguard. **Clean recorded R2 inputs after lease expiry** only touches the manifest's recorded objects after the 13-hour lease plus existing grace period. No customer objects are listed or removed. Keep the ledger, approvals, snapshots and saved MP4 on the persistent `/app/.data` volume.

## Server authorization — not enabled by this change

An owner must separately configure these server-only settings before the Start button can operate. This implementation neither modifies Railway nor deploys itself. Keep one Railway app replica with the existing persistent SQLite volume; do not run independent ledgers/replicas for the same one-test budget.

- Keep `DATA_DIR=/app/.data`, `DEMO_MODE=true`, `GENERATIONS_ENABLED=false`, `ADMIN_DEMO_ENABLED=false`, **`BYTEPLUS_LIVE_TEST_ENABLED=false`**, staging Basic Auth, Payload authentication and the exact HTTPS `CMS_ORIGIN`.
- Set **`BYTEPLUS_ADMIN_TEST_ENABLED=true`** only for the separately authorized admin test. Default is disabled.
- Require `BYTEPLUS_FIRST_TEST_ENABLED=true` and **`BYTEPLUS_FIRST_TEST_PLAN_ID` equal to the displayed prepared plan ID**. A different plan stays blocked.
- Set `BYTEPLUS_LIVE_TEST_OPERATOR_SECRET` to a private random value of at least 32 characters; `BYTEPLUS_LIVE_TEST_MAX_DURATION_SECONDS=5`; set both `BYTEPLUS_LIVE_TEST_MAX_JOB_MICRO_USD` and `BYTEPLUS_LIVE_TEST_MAX_TOTAL_MICRO_USD` to independently approved limits covering the reviewed inclusive bound. Zero/missing caps fail closed.
- BytePlus signing credentials: `BYTEPLUS_ACCESS_KEY_ID`, `BYTEPLUS_SECRET_ACCESS_KEY`.
- Private R2 credentials: `R2_ACCOUNT_ID`, `R2_BUCKET=singmotion-ai-private`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`. Keep public bucket access disabled.
- Set `BYTEPLUS_FIRST_TEST_DOWNLOAD_ENABLED=true` when explicitly authorizing the reviewed result fetch; the admin Start action now requires this gate beforehand. The UI's output approval is additionally mandatory.

The adapter passes an **isolated configuration copy** to the tested first-test workflow only after its separate admin gate passes. It never changes `process.env` or staging's prohibition on public/CLI live generation. Exact plan binding, operator secret, unchanged byte hashes, both spending caps, singleton slot, approval digest, uncertain-state handling, pinned-IP downloader and output media verification remain enforced by the existing backend. Restore admin/download gates to false when the test is finished. Review-field validity is not proof that account-specific billing evidence is true; the operator must substantiate it.

## Verification and remaining blockers

All automated provider/storage/output responses are mocked. Tests cover authenticated browser upload and unpriced review, Basic Auth, exact Origin, role/owner isolation, changed snapshots, size/duration limits, missing approvals, budget caps, duplicate/concurrent submissions, failed/canceled/uncertain tasks, same-task recovery and validated private MP4 storage. No real R2 or BytePlus requests were made. Production readiness still requires account-specific inclusive billing evidence and exact-host/media acceptance approval. No pricing or hostname assumption is introduced.

The normal demo cleanup retains immutable inputs referenced by the private test ledger, including unpriced admin plans. They require deliberate operator retention review; R2 lease cleanup does not delete the local reviewed snapshots.

The **Requirements blocking a paid start** checklist lists server gates, exact plan binding, secret/caps, credentials configuration, inclusive review, output approval and singleton/budget blocks. It does not contact services or verify the truth of operator evidence. After all listed blocks are resolved, the exact typed one-task confirmation is still required. No settings are changed by this UI.

## Practical first test

Use **Existing prepared plan ID → Load owned plan — no upload** to load the exact owned plan without replacing files. **Use one evidence-backed inclusive USD maximum** accepts a reviewed conservative total without claiming a tax/fee breakdown: those components remain null, not zero. Supply the generated-video upper bound and evidence supporting the total, all account-specific charges and compliance with the EUR budget using a defensible FX allowance. EUR 50 alone establishes none of these facts. The USD 0.28–0.42 display is an illustrative pre-tax base estimate for a 4–6-second generated video, not a quote for the input. The server records the actual authenticated reviewer and current review time. The sum-of-components review remains supported.

Select **First-test discovery** before the final paid confirmation to submit/poll once without unpublished output metadata. After observing the host, explicitly approve that exact host with evidence. The optional **Discover actual metadata** policy accepts only 720p short-side MP4, dimensions at most 4096, FPS >0 and ≤120, H.264/HEVC with AAC, and the approved duration range (minimum one second). These are operator acceptance limits, not asserted provider promises. Unknown fields stay unset. The existing pinned-public-IP, no-redirect transport and transfer limits apply; full FFmpeg validation must pass before private playback/download. Actual measured metadata is shown after validation. A changed host, unsupported file or exceeded duration remains blocked; do not submit a replacement paid task.
