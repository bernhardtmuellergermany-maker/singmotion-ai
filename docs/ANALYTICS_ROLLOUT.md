# SingMotion AI analytics rollout — November 26, 2026

## Scope and status
Existing Payload Customer Insights remain the authoritative source for actual customers, credit purchases, verified videos and refunds. Google Search Console is already verified for https://www.singmotion.ai/. No new database, advertising pixel or payment tracking is introduced. The website's English UI is retained.

The initial GA4 integration is for exact public marketing pages only. Private account, payment, admin, studio and project pages are excluded; query-bearing and fragment-bearing URLs are excluded entirely (including the home private carousel ?card parameter); referrer paths are not submitted as page-view parameters. Campaign IDs/UTM attribution, ad cookies and verified signup/purchase conversions are **not yet enabled**. Google Ads/Meta/TikTok integrations require separately approved consent purposes and implementation. Current Google tracking must remain disabled until the acceptance checklist below is complete.

## Configuration
- Staging: GA4_ENABLED=false and GA4_CONSENT_PREVIEW=true for UI-only review; the preview stores a distinct preference and never loads Google. If subsequently testing with GA4, use a dedicated test property, never the production ID.
- Production: GA4_ENABLED=false (or unset) by default, GA4_CONSENT_PREVIEW unset.
- GA4_MEASUREMENT_ID: real G-... web stream ID, separately set per environment only after verification. Never use an example ID. The browser only receives the public measurement ID if explicitly enabled.
- Consent preference stores version, decision and timestamp locally for 180 days; an ID-specific key prevents a preview decision from granting consent to a live property. No additional unique visitor identifier is generated by our app.
- Analytics consent defaults denied; advertising storage, user data and personalization remain denied. No Google script until affirmative consent and an allowlisted route. Withdrawal disables the tag, removes recognized GA cookies and reloads the current page. GA cookie lifetime is configured to 180 days without automatic renewal; verify effective settings in the real browser. A link from a tracked page into a private or query-bearing view uses a fresh document. Client navigation and cross-tab revocation also disable the tag and reload as needed; these are defensive controls, not proof of complete third-party script isolation.

## Google property checklist (operator approval required)
1. Create a dedicated, project-controlled Google Analytics account/property for Production and a separate test property for Staging, with least-privilege access and MFA. Use a business-controlled account, not shared credentials. Retain a handover checklist for a future buyer.
2. Configure the web stream for the correct hostname. Disable enhanced measurement, automatic history-based pageviews, Google signals, ad personalization, and unnecessary collection. Enable data redaction as an additional safeguard; choose and document retention (proposed 2 months for event-level data), review account data-sharing settings and cookie expirations.
3. Confirm Google contractual entity, Art. 28 terms, international-transfer safeguards, actual cookie/storage inventory, consent evidence and privacy notice. Obtain legal review before activation. The existing legal notice records outstanding vendor reviews; do not represent this as blanket compliance.
4. Verify the UI with desktop/mobile and keyboard, rejection before any Google network request (including on navigation), acceptance on an allowed marketing page, withdrawal and cross-tab behavior. Confirm expired/invalid preferences fail closed and private route transitions do not send personal URLs, identifiers, media, forms or page titles. Use DevTools and Tag Assistant with a test property; verify sanitized page parameters, referrer and hostname; confirm ad signals remain denied. A network audit is mandatory before activating real tracking.
5. Check GA4 DebugView and Realtime for accepted test visits only. Confirm staging and production are isolated. Review project release-parity policy; never force-promote divergent branches.
6. Only after the checklist passes, configure Production GA4_ENABLED=true with the verified production ID. Do not change public-access or crawler gates as part of this change.

## Future marketing and buyer readiness
Use the existing verified Search Console for organic search visibility; no HTML verification change is needed. Preserve aggregate monthly analytics exports and access ownership. GA4 visitor totals reflect consenting visitors, not every visit.
For paid campaigns, implement separately consented advertising features only after review, with explicit approved campaign metadata (no arbitrary URL values or personal data). For GA4 key events, add signup only after confirmed account creation and purchase only after verified settlement, deduplicating by a non-personal transaction key; never count a checkout click as revenue, never send emails, account IDs, project IDs or payment credentials. Existing credit ledger and refund figures are the authoritative business totals; don't invent recurring revenue or subscriptions. No new conversion emission, account linkage, Ads account or budget is configured by this change.
For handover, document property roles, data retention, consent and privacy obligations; transfer project-owned assets with appropriate legal basis, not raw customer information by default.

## Browser regression
Run `node --experimental-strip-types tests/analytics-consent.browser.ts` after building the application and installing Chromium through Playwright. The test uses an isolated local server, synthetic measurement ID, and intercepted mock Google tag; no requests to Google or real customer records are permitted. It checks no tag before choice, equal accept/reject controls, rejection persistence, one explicit page view after acceptance, no tag on private query URLs, and cross-tab revocation. It is not a substitute for the real-tag network audit with a separate test property.
